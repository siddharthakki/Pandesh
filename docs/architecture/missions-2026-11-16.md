# Missions: the operator layer (2026-11-16, branch `feat/jarvis-leap`)

Not merged, not installed. Built on main `c8a919b` (Build 178). Schema 53.

## What was missing

Pandesh already had specialists with frozen scopes, a governed hand-off, an evidence ledger, approvals, a capability
inventory, skills and a v2 window. What it could not do was the thing that makes those an operator: take one objective,
plan it across specialists, run it **without holding the conversation**, and report what was actually done.
`delegate_to_agent` made the lead wait (up to 15 minutes) for one specialist; nothing sequenced several; nothing survived
a restart; a finished child's approvals and results had no home in the chat.

## The layer (no second runtime, no second scheduler)

```
objective ─▶ lead plans (mission_start) ─▶ Core checks every step like a hand-off ─▶ durable mission
          ─▶ runner: each step = startDelegation + RuntimeExecutor (background lane) ─▶ evidence ledger per step
          ─▶ Core-written report in the conversation ─▶ clean missions saved as inactive skill drafts
```

| Piece | File | Reuses |
|---|---|---|
| Durable record (missions, steps, parallel flag) | `core/domain/missions.ts`, migration 53 | — |
| Runner: sequence, batches of ≤3 parallel steps, cancel, stop on failure, report | `core/runtime/missionRunner.ts` | `startDelegation`, `RuntimeExecutor`, `interactiveLane`, `delegationEvidence` |
| Lead tools `mission_start`, `mission_manage`; roster from agent definitions | `core/runtime/missionTools.ts` | agent definitions, hand-off preflight, approval cards |
| API + window card | `core/api/missionRoutes.ts`, `renderer-v2/src/Missions.tsx` | `listCapabilityActions`, `resolveAssistantApproval` |
| Experience | `missionProcedure` → `proposeSkill` | skill proposals (inactive, cleaned, owner reviews) |

Rules Core enforces (not the prompt):

- **Mode.** "…meanwhile I want to keep talking", "in the background": the turn is offered only the mission tools
  (`wantsBackgroundWork`). After `mission_start` succeeds, any other tool call in that turn is refused.
- **Independent check.** Asked for one (`asksForIndependentCheck`): a mission gets a review step whether or not the plan
  has it; a turn the lead did itself is handed to the Reviewer by Core and the result is attached. The doer re-running
  its own check is never reported as independent.
- **Evidence.** A step is `succeeded` only when recorded tool calls back it: the specialist's own tools or calls that
  bear on the request. Helpers (clock, arithmetic, skill lookup, memory recall) never count. Otherwise `unverified`, and
  the mission ends `completed_with_issues`.
- **Privacy between steps.** A step that may go online receives earlier results only from steps that could go online
  themselves; a local-only specialist's findings stay with local-only specialists.
- **Failure.** No automatic retry. A failed step stops the mission, later steps are `skipped`, its unanswered cards are
  expired, and the person can continue it. A restart marks running missions `interrupted` (never restarted on its own).
- **Authorization** is unchanged: every step is a delegated task with scope = specialist ∩ the turn's authority ∩ grant;
  internet use is asked once at `mission_start`; every write, command and GPU job still raises its own card.

## Specialists

- **Reviewer** is now the general independent check: adds `media_inspect`, read-only PC tools and approval-gated
  `run_checks` (it re-runs the project's tests itself).
- **Studio** (new definition): writes a script and produces media through one governed tool. It is a specialist
  configuration plus a tool adapter (`media_produce_video`, `media_inspect` in the existing media-production capability:
  Piper, the installed ComfyUI, FFmpeg). Nothing in the mission layer knows about video.
- `media_produce_video` / `media_create_video` are specialist-only: the lead plans, it does not produce.
- The lead's roster comes from the agent definitions, so a custom or disabled specialist changes what is offered with no
  code change.

## Fixes to existing behaviour found while exercising it

- The desktop host sent "create a 60–90 second … video, narrate it, subtitles, YouTube" to a 4-second text-to-video
  render before the lead saw it (`isVideoProductionRequest`).
- "Nothing is running in the background" was appended while a mission was running (`hasActiveWorker`).
- A delegated specialist could answer its brief with "Which one do you mean?"; one file under two spellings counted as
  two (`sameFileId`).
- A read-only specialist's task was judged "nothing was built" and escalated to a larger model.

## Not done / known limits

- **Lead quality varies.** The same request was planned well, planned with a needless step, and (before the mode rule)
  not planned as a mission at all. The 9B lead answered "17 × 23" correctly once and wrongly (401) once mid-mission.
- **Plan quality is the model's.** Core validates specialists and boundaries, not whether a step is the right step.
- **Review depth.** The Reviewer asserted things about pictures it had not looked at (it did not pass a `question` to
  `media_inspect`); in the creative run the rabbit is missing from several pictures and the upload sheet has no
  description or tags. Core's ledger shows which tools ran, not whether the judgement is right.
- **Desktop control** (UI Automation, input) is still absent: read-only screen capture and window list only.
- **External skills** are found and assessed as before; nothing new installs or runs them.
- Parallel steps are unit-tested with a stand-in executor, not yet exercised in a live run.
- No voice work in this pass. Mobile shows the report message, not the mission card.

## Trying it

1. Build (`node esbuild.core.js`, `node apps/desktop/esbuild.mjs`) and start an isolated instance.
2. Ask: "Find out what's slowing down my computer, work out what is safe to optimize, and have another specialist check
   the findings. Don't change anything. Meanwhile I want to keep talking to you."
3. Watch the mission card above the message box, ask something else, then "How is the mission going?".
4. Tests: `npx vitest run core/test/missions.test.ts core/test/missionMode.test.ts core/test/independentCheck.test.ts core/test/narratedVideo.test.ts apps/desktop/test/uiV2MissionModel.test.ts`
